# Состояние проекта на 5 июля 2026

Постоянное описание структуры проекта, образцов и служебных скриптов находится
в `QUICK_START.md`. Этот файл — краткий рабочий журнал.

## Сделано сегодня

- Зафиксирован baseline: `parse_variants.py` успешно разбирает все 16
  CSV-вариантов, `guess_variants.py` правильно определяет стиль всех 48 файлов
  CSV/XLS/XLSX.
- Проверки скриптов перенесены в параметризованные pytest-тесты.
- `Taxonomy` стал единственным объектом публичного API: `parser` и `reader`
  возвращают его, `serializer` и `writer` принимают его.
- Табличные адаптеры переименованы в `from_branches()` и `to_branches()`;
  понятие legacy-режима удалено.
- Сериализация всех 16 стилей проверяется точным сравнением с CSV-образцами.
- Модель получила структурное сравнение, проверку наличия пути, leaf-пути,
  безопасное обновление листьев и удаление узлов/поддеревьев.
- Представления листьев и дочерних узлов доступны только для чтения; изменение
  выполняется через валидирующий API `Taxonomy`.
- Удалены неиспользуемые переходные функции и исправлены замечания типизации.
- README приведён в соответствие с новой моделью.
- Добавлены 48 настоящих round-trip тестов записи и повторного чтения всех
  16 стилей в CSV/XLS/XLSX.
- `generate_variants.py` создаёт 48 корректных файлов; каждый повторно
  импортирован и сверен с эталоном. Ошибка отображения `styler` в журнале
  генератора исправлена.
- `generate_google.py` успешно создаёт большие CSV/XLSX и подтверждает
  совпадение четырёх проверяемых результатов с исходной таксономией.
- Добавлен воспроизводимый `Scripts/benchmark_model.py`. На Google CSV из
  5595 узлов модель занимает около 1,985 MiB против 2,006 MiB у таблицы полных
  ветвей (99,0%); импорт занимает около 0,16 с, поиск всех узлов — 0,024 с.
- Дочерние словари теперь создаются лениво, ID хранится один раз на входящем
  ребре, а не дублируется в узле.
- API редактирования дополнен перемещением поддеревьев, переименованием ID,
  выборками и стабильными preorder/postorder/breadth-first обходами.
- Добавлены синтетические memory-тесты трёх форм дерева. Отношение памяти
  `Taxonomy` к таблице полных ветвей: глубокое дерево — около 44%, широкое —
  97%, сбалансированное — 92%.
- Текущий Python-trie признан достаточным для версии 0.1: он не проигрывает на
  широком дереве и существенно выигрывает по мере роста глубины. Более
  компактное arena-представление пока не оправдывает дополнительную сложность.
- В начало README добавлено подробное руководство по публичному API: создание,
  импорт, парсинг, поиск, обходы, добавление, обновление, переименование,
  перемещение, коллизии, рекурсивное удаление, сериализация и исключения.
- `IpStyle` и `LpStyle` экспортируются верхнеуровневым пакетом. Примеры README
  защищены отдельными исполняемыми тестами `test_public_api.py`.
- Реализован отдельный слой пользовательской валидации внешних таблиц:
  `ValidationIssue`, `ValidationReport`, `validate_input()` и
  `TxInputValidationError`.
- Валидаторы покрывают общую структуру, все IP/LP-комбинации, заголовки,
  key/value-группы, ID и ID-пути, плотные и sparse leaf-пути, дубликаты и
  невозможность восстановления sparse-значений.
- `parse_taxonomy()` и `import_taxonomy()` валидируют данные автоматически и
  возвращают одно информативное исключение со всеми найденными проблемами.
  Имя файла, строки и столбцы включаются в отчёт; исходные исключения парсера
  сохраняются только как `__cause__` для разработчика.
- Добавлен `validate_taxonomy()` для аудита готовой модели. Ошибки конфигурации
  `leaf_keys` файлового импорта также используют общий формат отчёта.
- Все 16 эталонных стилей проходят валидацию; повреждённая строка каждого из
  16 стилей обнаруживается. Отдельно проверены агрегация ошибок, warnings,
  лимит диагностик, машиночитаемый `to_dict()` и сообщения с именем файла.
- README дополнен подробным руководством по ручной и автоматической валидации.
- Большой Google-генератор и все варианты повторно прошли с включённой
  автоматической валидацией.
