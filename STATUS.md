# Состояние проекта на 8 июля 2026

Постоянное описание структуры проекта, образцов и служебных скриптов находится
в `QUICK_START.md`. Этот файл — краткий рабочий снимок состояния проекта.

## Сделано к текущему состоянию

- `Taxonomy` остаётся единственным объектом публичного API: `parser` и
  `reader` возвращают его, `serializer` и `writer` принимают его.
- Модель хранит таксономию как prefix-forest: полный путь узла является его
  идентичностью, общие префиксы разделяются, дочерние словари создаются лениво,
  ID хранится на входящем ребре и не дублируется в узле.
- Поддержаны основные операции модели: добавление ветвей, обновление листьев,
  структурное сравнение, проверка наличия пути, получение узла, удаление
  узлов/поддеревьев, перемещение поддеревьев, переименование ID, выборки и
  стабильные обходы `preorder`, `postorder`, `breadth`.
- Представления листьев и дочерних узлов доступны только для чтения; изменение
  выполняется через валидирующий API `Taxonomy`.
- `leaf_path(path, key, missed_leaf="auto")` возвращает путь листьев от корня
  до узла. Пропущенные листья обрабатываются так же, как в сериализации:
  `"auto"`, `None` или пользовательская функция.
- Добавлен `iter_leaf_paths(key, order="preorder", missed_leaf="auto")`:
  итератор возвращает пары `(id_path, leaf_path)` и накапливает leaf-путь во
  время обхода, без повторного прохода от корня для каждого узла.
- Реализован слой пользовательской валидации внешних таблиц:
  `ValidationIssue`, `ValidationReport`, `validate_input()`,
  `validate_taxonomy()` и `TxInputValidationError`.
- `parse_taxonomy()` и `import_taxonomy()` валидируют данные автоматически и
  возвращают одно информативное исключение со всеми найденными проблемами.
  Имя файла, строки и столбцы включаются в отчёт; исходные исключения парсера
  сохраняются как `__cause__`.
- При импорте/парсинге строковые ячейки, строковые ID, ключи листьев и значения
  листьев нормализуются через `strip()`. Нестроковые значения не изменяются.
- Реализована работа с IP-обрезками уникальных ID:
  `restore_unique_ip_chunks(chunks)` восстанавливает полные IP-пути,
  `split_to_unique_ip_chunks(taxonomy, max_chunk_len=2)` выполняет обратное
  дробление.
- `parse_taxonomy()` и `import_taxonomy()` поддерживают
  `restore_ip_chunks=True` для IP-стилей. При неоднозначном родителе, цикле или
  конфликтующих листьях возникает `TxParsingError`.
- `serialize_taxonomy()` и `export_taxonomy()` поддерживают
  `max_chunk_len: int | None = None`. Для `IpStyle` это сохраняет таксономию
  как IP-обрезки заданной максимальной длины; для `LpStyle` параметр считается
  ошибкой конвертации.
- Добавлена явная API-функция `renumber_taxonomy_ids()` для переназначения ID
  таксономии, включая случаи, когда старые ID уже есть, но не подходят из-за
  неуникальности или старой схемы.
- Все 16 эталонных стилей чтения, определения стиля и сериализации покрыты
  тестами на существующих образцах. Файловые драйверы проверены реальной
  записью и чтением CSV/XLS/XLSX.
- Добавлены настоящие round-trip тесты записи и повторного чтения всех 16
  стилей в CSV/XLS/XLSX.
- `generate_variants.py` создаёт 48 корректных файлов; каждый повторно
  импортируется и сверяется с эталоном. `generate_google.py` создаёт большие
  CSV/XLSX и сверяет проверяемые результаты с исходной таксономией.
- Добавлен воспроизводимый `Scripts/benchmark_model.py`. Текущий Python-trie
  признан достаточным для версии 0.1: он существенно выигрывает на глубоких
  деревьях и не проигрывает критично на широких.
- README приведён в соответствие с текущей моделью и публичным API: создание,
  импорт, парсинг, валидация, поиск, обходы, leaf-view, редактирование,
  сериализация, IP chunks и исключения.
- `Examples/example.py` обновлён под актуальное расположение brief samples и
  сценарий чтения IP chunks.

## Инварианты

- ID узлов и ключи листьев — любые непустые хэшируемые объекты.
- Значения листьев — любые объекты, включая `None`.
- Полный путь узла является его идентичностью в модели; одинаковый ID может
  встречаться в разных ветках обычной таксономии.
- Восстановление и дробление IP chunks возможно только для таксономий, где ID
  узлов глобально уникальны.
